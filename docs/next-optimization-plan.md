# 下一步优化计划

本轮已完成请求层错误归一、URL 安全边界、上传校验复用、状态组件复用和相关单元测试覆盖。下一阶段建议围绕用户体验、服务稳定性和安全性继续推进。

## 用户体验

1. 将 `AppState` 推广到通知、用户中心、详情页等空态/错误态，统一 loading、empty、error、retry 的视觉和交互。
2. 为图片加载失败增加占位图和重试入口，避免卡片、详情图和头像出现破图。
3. 搜索页保留筛选条件、分页和滚动位置，提升前进后退与直接打开链接时的一致性。
4. 上传流程增加进度、失败重传和未发布离开提醒，降低多图发布的误操作成本。

## 稳定性

1. 为列表请求增加取消或去重策略，避免快速切换筛选时旧请求覆盖新结果。
2. 建立统一 API 响应 normalizer 清单，收敛 `items/records/list`、`total/count` 等后端兼容逻辑。
3. 在关键页面补充错误边界和降级数据策略，确保局部接口失败不会拖垮整个页面。
4. 将覆盖率目标提升到 60% 以上，优先覆盖请求拦截、路由守卫、上传下载和用户态同步。

## 安全

1. 下载 token 建议后端改为短期一次性凭证，前端继续只允许 http/https 新窗口打开。
2. 图片 URL 校验继续保留协议白名单，并在卡片、详情、头像入口统一使用。
3. 补充依赖审计和构建产物检查，关注大体积 vendor chunk 与过期 Browserslist 数据。
4. 对上传文件增加后端 MIME 与内容签名校验，前端校验只作为体验优化，不作为最终安全边界。
